# 游戏文字数据源比较

核对日期 2026-09-25。这个比较只回答训练文字从哪里取得，不把仓库切换本身当作 OCR 准确率提升。

## 结论

- 正式数据使用 [ArknightsAssets/ArknightsGamedata](https://github.com/ArknightsAssets/ArknightsGamedata) 提交 `09df1ef62bb5e1ea3e22549a5b280c7083c85de4`。同一提交提供 `cn`、`tw`、`en`、`jp`、`kr`，适合按提交和逐文件哈希冻结五语言材料。
- [Kengxxiao/ArknightsGameData](https://github.com/Kengxxiao/ArknightsGameData) 仍适合作为中国服字段的交叉核对来源，但主分支只提供 `zh_CN`，不能独立承担本轮五语言输入。
- 正式语料按明确字段抽取 25,358 条。来源锁、文件哈希和 JSON 指针都进入数据配方。
- 2026-09-24 的中国服控制变量核对中，两仓库最新快照经过本项目实际读取的五张表与字段白名单后，均为 5,567 条记录、4,599 个唯一文字；文字差异为 0。因此没有可供训练 A/B 的中国服文字自变量，也不宣称切换仓库会直接提高准确率。

| 比较项 | ArknightsGameData | ArknightsAssets/ArknightsGamedata |
|---|---|---|
| 本轮用途 | 中国服交叉核对 | 五语言正式来源 |
| 区域 | `zh_CN` | `cn`、`tw`、`en`、`jp`、`kr` |
| 固定方式 | 提交/文件可固定 | 提交/文件可固定 |
| 中国服白名单文字 | 与右侧相同 | 与左侧相同 |
| 选择理由 | 中国服维护清晰 | 五语言同一版本、更新及时、便于统一审计 |

## 什么时候才需要模型控制变量

只有规范化后的实际训练文字出现差异，才值得训练 A/B。届时固定预训练权重、字典、字体、背景、样本数、分区、训练步数、学习率、随机种子、导出和 MAA 推理接口，只替换语料；同时报告来源独有文字、真实截图和至少三个训练种子。若差异仅在仓库目录或未读取字段，停止实验。

本轮准确率来自场景生成、采样、微调和独立验收的组合，不能归因于仓库名称。
