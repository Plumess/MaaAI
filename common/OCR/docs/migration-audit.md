# 工程整理与决策追溯

这份文件说明试验工作怎样收敛为可维护 PR。原则是：只迁入后续训练和验收仍会使用的通用入口；原始截图、数据、权重、日志和一次性试验留在外部交接包；关键结论由哈希和正式报告索引。

## 已保留的正式能力

| 环节 | 入口 | 解决的问题 |
|---|---|---|
| 固定环境 | `environments/train`、`setup`、`doctor` | uv 锁定 Python 包；固定 PaddleOCR、MAA v6.18.0、预训练权重和原生运行库，发现版本/哈希漂移立即停止 |
| 数据来源 | `fetch`、`corpus` | 五语言游戏字段、字体和公开素材按提交/文件哈希获取；每条文字保留 JSON 指针 |
| 截图与校准 | `capture-unpack`、`capture-import`、`review`、`calibrate` | 保留原图、会话和裁剪关系；拟合图与检查图分开；OCR 输出不会自动成为真值 |
| 数据生成 | `generate`、`scene`、`audit-pool` | 修复字形边界、空格、无限重试和重复标签；记录逐图参数、来源、分区与像素哈希；自动联系表已删除，正式输出只保留数据和审计 |
| 字典与模型 | `prepare-model`、`warm-symbols` | v6 保持官方字符顺序，Char 做 ASCII 映射，韩文新增字符只更新对应输出列 |
| 训练 | `plan`、`train` | 冻结所有输入，使用发布预处理、固定采样/预算、GPU 互斥、断点和失败停止 |
| 导出 | `export-check` | 处理 PIR/`linear_v2`/LayerNorm，比较 eager、PIR、ORT 和 MAA 发布运行库 |
| 质量与性能 | `freeze-evaluation`、`inspect-rules`、`evaluate` | 开发选版、独立真值、任务规则、整帧业务和性能记录分开；双方同错不算通过 |
| 交接 | `package` | 只打包六路线的 6 个 rec ONNX 和 6 个字典，拒绝未锁定文件和额外资源 |

试验阶段的 `configs/s2`、`s2_render.py` 与 `data/s2/word` 是工作目录命名，不是上游兼容接口。正式入口分别改为 `configs/dataset`、`core_training_data.py` / `scene_style.py` 与外部 `data/assets/word`；未进入本轮正式生成主链的字形图集能力移到 `pipeline/experimental/`。36 个素材锁条目逐项核对仍指向原训练时相同的文件哈希。历史训练计划和模型证据保留旧路径与旧源码快照，不据此宣称重新训练。

## 最终执行状态

- 在新外部目录中从零建立环境，环境审计通过。
- 冻结 82,000 张正式基础数据并完成六路线训练；五条 Word 路线与 Char 基础模型选择第 500 步。Char 后续加入 448 张已复核真实裁剪变体并选择返工 step 100。
- 五条 Word 与 Char 基础模型各通过 42 项导出一致性；formal-v2 Char 通过 46 项。韩文第 1,000 步因导出不一致被拒绝。
- 使用 MAA v6.18.0 原生分析器完成国服独立回放：8 张不同截图、10 个案例；其中 9 项正向通过、1 项仓库“全部”页为双方共同失败，不能记为正确。其余仓库数量及关卡掉落按已复核真值记录。
- Windows v6.18.0 对 formal-v1 的 A/B 隔离、发布核心资源注册和国服主业务回放已完成；10,107 个文件中仅 12 个候选资源变化。其后发现的 `0-1→O-1` 已由 formal-v2 修复；Linux 与 Windows 的原生接口、完整分析器、两层资源隔离和真实费用 0 均通过。原国服业务集保持 9 项正向通过、1 项已知共同失败；五条 Word 路线保持冻结。
- 正式候选 ZIP 只含 12 个资源文件。外服实图仍需补测；Windows 发布版 GUI 的国服公招与仓库已通过，原版 DLL 没有离线图片直调内部 OCR 的公开接口；性能为未来优化项。

精确结论和哈希见 [正式训练报告](final-training-report.md) 与 [机器证据](final-training-evidence.json)。

## 没有进入 Git 的内容

- 82,000 张基础训练/开发图、448 张 Char 真实裁剪变体及其压缩包；
- 六条路线权重、恢复点、ONNX 候选包；
- 私人截图、完整日志、编译产物、下载缓存和第三方仓库；
- 失败的首次正式计划和一次性批量分析脚本；
- 量化、后端替换等没有形成主线收益的试验产物。

这些材料只在交接目录保存必要的最终包、冻结哈希和可追溯记录。PR 中保留能重新生成它们的代码、锁文件、训练策略、测试和结论，不保留随机预览图或中间 checkpoint。

## 关键决策为什么这样做

1. 直接基于 MaaAI main 开发；#14 和 #18246 只作为参考，逐项吸收，避免把未合并 PR 当基线。
2. ArknightsAssets 用于五语言统一冻结；中国服与 ArknightsGameData 的实际文字字段等价，因此不把数据仓库切换包装成准确率收益。
3. 五条 Word 路线的 20k 扩量没有稳定收益，正式版保留 10k；Char 的 20k/500 有收益，单独扩量。
4. 国服独立实图是本轮质量主标准；外服开发集只能支持继续测试，不能替代真实客户端验收。
5. 性能门槛本轮取消。模型质量和运行后端分开判断，避免用未经验证的后端收益解释模型变化。
